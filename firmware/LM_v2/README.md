# LM V2 bench firmware

Open `LM_v2.ino` in Arduino IDE. Select the original ESP32 Dev Module (ESP32-WROOM-32E, no PSRAM), not ESP32-S3 or C3. Requires the Arduino-ESP32 core with Bluetooth Classic SPP. USB serial: 115200; Mission Control UART2: 19200 baud, 8N1, RX GPIO16, TX GPIO17. Bluetooth device name HAM-LM-V2. Wi-Fi disabled by default. Status LED indicates an active SPP client; activity LED indicates traffic.

This is a byte-transparent bidirectional bridge between Mission Control and Bluetooth; USB is a read-only mirror/diagnostic console. It preserves CR/LF bytes and does not silently translate commands. The archived Ground_Control sketch forwards telemetry to Serial2 at 19200, and `processTPInput` forwards newline-terminated commands to the radio. Original Telemetry_Processor parses telemetry, position, battery and status and renders an ANSI terminal display; this draft does NOT implement that processing yet. Its exact original code is preserved in `reference/Telemetry_Processor.ino.txt` (non-compiling reference). The old antenna-control path and physical logging switches were intentionally omitted per the new two-connector architecture.

**Not tested/compiled in this environment.** Use a disconnected bench setup with a loopback or simulated Mission Control. Bluetooth commands are not authenticated by an application-level authorization protocol. Do not use with a live mission until pairing/authorization, buffer overflow/latency, parser regression and command framing are verified. Bluetooth library writes may block on congestion. USB output may drop bytes to avoid blocking. No persistent logging is included. Porting and testing the existing parser and terminal presentation remain a separate implementation task.
